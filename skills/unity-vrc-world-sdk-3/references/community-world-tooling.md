# Community world tooling — source review 2026-09-12, updated 2026-10-13

Documentation research, not an installation or runtime compatibility test. These are third-party tools/recommendations, not personal user preferences or required packages. Versions below are source snapshots, not a promise that any package works with every newer Worlds SDK. Prefer the project's existing solution; add a dependency only for a demonstrated need.

## Choose by problem

| Need | Candidate | Main gate |
|---|---|---|
| Playable pool/snooker, practice and shot replay | MS-VRCSA Billiards | Layer 22 takeover; author explicitly leaves Quest compatibility unverified |

| Audio-reactive visuals for a requested music/club feature | AudioLink (VCC Curated, `com.llealloo.audiolink` 3.x) | Only when a world asks for it; press "Link all sound reactive objects to this AudioLink" after placing the prefab; script readback is experimental |

## MS-VRCSA Billiards

- Fork lineage: Pool Parlor by metaphira/Toasterly, originally Harry-T; updated by Neko Mabel and Sacchan. Intended for more realistic cue sports and quality-of-life features, not a generic Rigidbody/ObjectSync table.
- README features: selectable table models and physics scripts; cue length/smoothing; multiplayer undo/redo/skip; leave/rejoin and automatic single-player practice mode; save/load ball layouts or in-flight shots; predictive collisions/substeps and jumping/rail physics; 6-red snooker; distance LoD disabling simulation/visuals; nine table variants, including VRCBCE-derived tables.
- Multiplayer undo/redo assumes trust between players. The README says two-client local Build & Test works and mentions syncing player IDs instead of names. Treat claims of good pool synchronization as **third-party recommendation/source claims, not our tested guarantee**. Before adoption, exercise late join, departure mid-shot, ownership changes, spectator LoD re-entry and restore/undo with real clients.
- Install the released `.unitypackage` through Unity; README then calls `MS-VRCSA > Set Up Pool Table Layers` and places a prefab from `Prefab/`. That setup **renames layer 22 to BilliardsModule and changes its collision matrix to self-only**. Audit existing layer-22 uses first; do not silently run it in a populated world.
- Swappable tables are not straightforward to lightmap. README recommends keeping only one table under `BilliardsModule/intl.table/` if lightmapping. Alternatively, its custom table shader has a `_VRCLV` variant for VRC Light Volumes; this is optional integration, not an automatic dependency or proof of support for every Light Volumes version.
- Custom tables start from an existing prefab and adjust ModelData/gizmos to match geometry. Preserve hierarchy names starting with a period; source says code uses them.
- No root package/VPM manifest or numeric SDK/Unity requirement was present in the reviewed root inventory/README/release. Do not invent a supported version range. The README explicitly says Quest setup was neglected and the author does not know whether it still works.
- Maintenance signal: latest release endpoint returned **1.14, published 2025-06-08**; repository metadata showed a push on **2026-09-04**, but README still says the author does not intend further major work. Recent activity does not negate that warning. 1.14 fixes include spectator/LoD pocket-blocker state and team inversion switching to snooker; cue pickup fix is phrased as tentative by the author.
- Licensing is mixed in the tree: [root LICENSE.md](https://github.com/Sacchan-VRC/MS-VRCSA-Billiards/blob/master/LICENSE.md) is MIT-style, copyright 2024 Sacchan-VRC/NekoMabel; [BilliardsModule/LICENSE](https://github.com/Sacchan-VRC/MS-VRCSA-Billiards/blob/master/Modules/BilliardsModule/LICENSE) contains the Unlicense. Preserve both and relevant upstream notices. Do not flatten the entire fork or all included art to public-domain/CC0 based on the nested file.

**Workspace policy, separate from upstream instructions:** do not add table/furniture colliders or stations for convenience. Only explicitly requested gameplay pickups get the tight primitive collider they require; preserve necessary game mechanics deliberately. Imported pickups must follow workspace proximity `0.1` / Auto Hold `No` rules (2026-09-15 supersedes older proximity guidance). A source recommendation is not authorization to import the game or make scenery interactive.

## VizVid (repository VVMW)

### Fit and installation

- Modular frontend with AVPro, Builtin and PNG/JPEG image backends; screen/audio/UI can be separated. Includes playlists, user queue/history, seek/repeat/shuffle, synchronization or local-only mode, backend fallback/retry handling, on-screen/separate/overlay controls and localized UI. Use one Core per independent player; many screens need not mean many decoders.
- Exhibition presets are local-only with proximity playback; social/event presets can synchronize. Optional features include portable **local** screen, background-audio ducking, resync controls, stream key assignment, AudioLink, LTCGI, YTTL titles and VRC Light Volumes updates. Integrations need their own packages/settings/shader support; they are not blanket prerequisites for basic playback.
- Recommended install is VCC: add [the author's VPM repository](https://xtlcdn.github.io/vpm/), then add **VizVid** (`idv.jlchntoz.vvmw`) in Manage Project. The README also documents `vrc-get`, Booth and GitHub release routes. **The 1.8.0 release explicitly discourages manually importing its assets because dependencies will be missed.** Do not treat a downloaded unitypackage as self-contained.
- Manifest snapshot: package **1.8.0**, `unity: 2019.4`, `vrchatVersion: 2022.1.1`; VPM requirements are `com.vrchat.worlds: 3.x.x >=3.10.2`, `idv.jlchntoz.vrcw-foundation: 0.x.x >=0.0.65`, and `idv.jlchntoz.lazyswitch: 0.x.x >=0.8.3`. The old Unity/VRChat metadata fields are **not** instructions to downgrade the supported world editor or evidence of testing on those old versions. Resolve the selected release's dependencies in the actual project; a minimum SDK requirement is not certification of all future SDKs.
- Add a preset from the Hierarchy context menu `VizVid`; choose only necessary modules. Playback-speed control depends on **AVPro Stub** per manual; title/playlist fetching involves YTTL/yt-dlp. Do not install optional helpers unasked.

### Platform, playback and operational caveats

- PC and mobile can require different URLs, especially live streams. Playlists support separate PC/Quest URLs; alternative URL input and Stream Key Assigner also support mobile alternatives. Auto-filled Quest URLs are not proof that the same protocol/codec/host works on both platforms.
- Low-latency mode is for AVPro live playback; README reports testing RTSP/RTMP, not every streaming service. Use the actual event stream in both target clients. The manual directs VizVid testing to **SDK local Build & Test**, not Unity Play Mode alone.
- Backend distinctions are about media/protocol/runtime, **not “Unity cannot play YouTube.”** [Official VRChat video documentation](https://creators.vrchat.com/worlds/udon/video-players/) ([readable source](https://github.com/vrchat-community/creator-docs/blob/main/Docs/docs/worlds/udon/video-players/index.md)) says Unity's backend can play supported hosted services in the client; its Editor preview needs direct supported files. AVPro supports the documented YouTube Live/Twitch streams whereas Unity's backend does not. Android now has URL resolution; the old blanket “Quest has no resolver” workaround is historical.
- Official docs specify one new video URL per **five seconds per user across all players**, including default URLs and late-join loads. VizVid's debounce/rate-limit handling does not establish that every unrelated player in the world is coordinated. Audit simultaneous startup/late joins rather than assuming multiple players are safe.
- Hosts outside VRChat's allowlist require the viewer's Allow Untrusted URLs setting, and in Public/Group Public instances also the world's **Video Player Allowed Domains** entry on vrchat.com (see [audio-video.md](audio-video.md#types-and-features)). A frontend cannot bypass that or guarantee host availability. Source/backend/encoding/platform restrictions still apply even when a URL resolves.
- Manual says Builtin supports only one output AudioSource; use stereo output there. VizVid's AVPro setup supports separate stereo/5.1 sources; do not assume a multichannel AVPro layout survives fallback to Builtin without checking the result.
- If changing default volume appears ineffective, existing persisted user settings can win. Manual says resetting that world's user data restores defaults; do not erase user data automatically as a “fix.” YT-DLP update is a documented troubleshooting option for editor title/playlist fetching, not a guarantee that client playback is repaired.
- Maintenance signal: **1.8.0 published 2026-09-03**, with matching manual and manifest. Notes include YouTube failure messages, Light Volumes V3 cookie support, stereo/5.1 configuration and exhibition/playlist fixes. Keep release-specific instructions together. Latest as of 2026-10-13 is **1.8.2 (2026-09-24)**; its notes were not reviewed here.
- MIT, copyright 2023–2026 Jeremy Lam/Vistanz, Yama Buta and contributors. Preserve license/copyright for copied substantial portions; the project explicitly says **not public domain or CC0**. Existing notices are included for ordinary Unity/VRChat use; do not remove them. Linked music, videos and images require their own permissions.

## GI Tweaks

- Editor GI tooling, **not a replacement lightmapper, runtime GI system, or universal VRChat optimization switch**. README says tested with **Unity 2022.3, Built-in Render Pipeline**; supports Unity Progressive and Bakery with feature exceptions. Manifest is **0.1.3**, Unity **2022.3**, with no declared package dependency list; bundled Harmony performs patches. No specific VRChat SDK/Bakery version range is stated.
- Prefer the documented [VCC repository route](https://pema99.github.io/vpm/redirect.html) in this workspace. README also offers UPM git URL `https://github.com/pema99/GITweaks.git` and release/disk install; its instruction to select a downloaded ZIP in “Install package from disk” is source advice, not an install flow verified here. Use the appropriate extracted package/manifest workflow for the installed Unity Package Manager if needed.
- All tweaks toggle at `Tools > GI Tweaks > Settings`. Useful diagnostics: clickable lightmap charts, atlas-index picker, bulk renderer selection, baked-transmission visualization, expanded LightingDataAsset inspector, material GI flags. Convenience patches add embedded/default Lighting Settings, skybox New/Clone, and lightmapped-to-probe-lit conversion without a new bake. Inspect changes rather than enabling every toggle on an established project.
- **Shared LOD** reuses lightmap space across LOD levels by modifying stored LightingDataAsset, avoiding runtime index/offset fiddling. Treat compatible authored UV correspondence as an adoption check, not an automatic fix for arbitrary unrelated LOD meshes; prefer an existing Bakery SharedLODUV workflow rather than stacking both blindly.
- **Optimize lightmap sizes after baking does not work with Bakery** and is disabled by default. For Unity's baker it repacks under-covered maps without resizing each instance; coverage threshold and minimum size control the tradeoff. The README's 512² → two 256² example halves texels in that scene; it is not a universal VRAM reduction guarantee.
- **Seam Fix / Seam Fix Volume** targets hard seams between renderers caused by bilinear filtering, not different lighting colors, wrong UVs, geometry leaks or bad GI sampling. Keep volumes local and exclude intentional boundaries; broad volumes can be expensive. Preview/Reset is non-destructive; **Apply modifies lightmap textures on disk**. Preserve the bake before experimenting.
- LightingDataAsset inspector edits can corrupt the bake; README suggests rebaking for recovery. Harmony/internal-editor patches make Unity upgrades a compatibility checkpoint. No runtime or bake testing was done here.
- Maintenance signal: latest release returned **0.1.3, 2024-11-13**, a chart-picking conservative-rasterization hotfix. Current license says **BSD-3-Clause**, copyright 2026 Pema Malling; bundled Harmony is MIT. Preserve notices/disclaimers and BSD non-endorsement terms. An old release date alone is not proof of abandonment; current branch and packaged release licenses may differ, so retain the actual version's notices.

## XatlasLightmap: chart packing, not “install xatlas for Bakery”

- This is z3y's **Bakery-only atlas packing integration**. It starts from generated/custom lightmap UV2 and creates unique UV2 per mesh instead of normal lightmap scale/offset use; editor additional vertex streams require Bakery script modifications. README claims uniform texel density at scale 1 and no extra cost with static batching; these are source claims, not a measured workspace result.
- Author's setup: UPM git `https://github.com/z3y/XatlasLightmap.git`; `Tools > XatlasLightmap > PatchBakery` once; add `XatlasLightmapPacker`; assign a BakeryLightmapGroup with **Packing Mode = Original UV**; provide generated/custom UV2, enable model mesh Read/Write, then Pack. This is an invasive optional workflow, not permission to patch the installed Bakery package here.
- **Separate unwrapping from packing.** Unwrapping creates mesh charts; atlas packing arranges charts/layouts into shared textures. [Bakery's own manual](https://geom.io/bakery/wiki/index.php?title=Manual#Unwrapper) already documents an xatlas **Unwrapper** for Adjust UV Padding and an xatlas **Atlas Packer** for arranging object layouts, including hole filling/LOD packing. The external tool is a different integration, not a missing library every Bakery project needs.
- **Avoid double processing:** first inspect Bakery's existing packer/UV settings and atlas preview. If intentionally adopting the external tool, preserve its packed UV2 using the documented **Original UV** group (Bakery defines that as no packing); do not then run a competing re-unwrap/repack over those same outputs. Repack after source geometry/UV changes and rebake with consistent layout. Prefer native Bakery controls when they already solve the problem.
- README limitations: **no nested lightmap groups; no GPU instancing** because meshes become unique; only static batching. Model reimport breaks the packed mesh until packed again. Two-pixel padding can bleed with common shaders; author recommends a centroid lightmap-UV interpolator, and bicubic sampling needs more padding. First bake can fail; build UV2 access can fail when Read/Write is disabled. Inspect the actual bake/build rather than trusting editor preview.
- Manifest current branch: **0.3.0**, Unity **2019.4** metadata. Latest GitHub release endpoint instead returns **v0.1.6, 2024-09-03**, whose note says it fixed patching for the then-“latest Bakery.” This mismatch means branch and release are not interchangeable; that historical wording is **not** a guarantee for Bakery 1.98, current Unity or latest Worlds SDK. Select/pin the intended revision and inspect its patch against the installed Bakery before adoption.
- MIT copyright 2023 z3y, plus bundled xatlas MIT copyright 2018–2020 Jonathan Young. Editor README attributes native-source provenance to [guycalledfrank/xatlasLib](https://github.com/guycalledfrank/xatlasLib). Preserve bundled notices; Bakery itself remains a separately licensed dependency.

## LTCGI (opt-in video/emitter room light)

- **What it is:** shader-evaluated area lighting and reflections (linearly transformed cosines) from screens and emissive panels, with an optional baked shadowmap. It is **not a Unity Light**, but it **is realtime lighting with a per-frame GPU cost**. Under the fully baked default it is opt-in only: offer it when a world wants video-lit rooms, log the user's explicit decision in WORLD.md, ship it behind a user toggle, and measure GPU ms with it on and off.
- **Shaders:** only receivers with an LTCGI-capable shader are lit. lilToon (≥1.8) supports it; stock Standard does not, and switching to ORL/Filamented/Mochie/Graphlit needs the user's explicit request (shader rule).
- **Setup:** exactly one `LTCGI_Controller` per scene (editor-only, not uploaded). Video players connect through adapters from the Releases page (pairs with ProTV 3+); test with a static texture first. List material-swapping receivers under **Dynamic Renderers**.
- **Bake:** receivers must be Static with valid lightmap UVs. Use **"Bake LTCGI Shadowmap and Standard Lightmap"**; a shadowmap-only bake leaves the shadowmaps displayed instead of your lightmaps. Re-bake reflection probes afterwards, as after any bake. A failed bake can leave screens tinted R/G/B: press "DEBUG: Force Settings Reset after Bake".
- **Static batching:** LTCGI disables static batching on receivers during the shadowmap bake (baked `unity_LightmapST` breaks its offsets). "Allow Static Batching (EXPERIMENTAL)" (1.7.0+) can desync UVs; verify in play mode and count the draw-call cost either way.
- **Versions:** 1.7.3 (2026-08-02) is current; supports VRC Light Volumes since 1.7.0 (1.7.3 fixes LV 3.0.0-dev.14+, older LV 2.x builds have hit compile errors, LTCGI#48).
- **Licence:** MIT plus mandatory attribution: the `LTCGI Attribution` prefab or a visible link to github.com/pimaker/ltcgi.

## VRWorld Toolkit (pre-upload audit and build-size report)

- VCC Curated `dev.onevr.vrworldtoolkit`, V3.5.1 (2026-10-08), requires Unity 2022.3, MIT.
- **World Debugger:** 90+ scene checks; messages can be marked ignored. **Build Report** reads the SDK's last Windows/Android build report (size per asset); 3.5.0+ captures builds via a hook, archives past reports and adds a **Build Report Comparison** window for before/after optimisation passes. Upload size and frame cost are separate problems; this answers only the first.
- Also: Mass Texture Importer (batch max size/compression per platform), mirror layer presets, a `DisableOnBuild` tag (disables, does not strip).
- **Don't apply Auto Fixes blindly.** Its one-click Post Processing setup and crunch defaults are suggestions; crunch shrinks download, not VRAM. Check each fix against workspace rules first.
- If it fails to compile after Bakery or Post Processing v2 was removed, delete the stale `BAKERY_INCLUDED` / `UNITY_POST_PROCESSING_STACK_V2` define (see `vrchat-world-gotchas`).
