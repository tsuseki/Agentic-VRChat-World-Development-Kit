# Low-poly tree generation (Blender script pipeline)

Proven method: a family of 11 trees (6 olive variants, Japanese maple, Italian cypress, birch clump/single/weeping, ficus, stone pine) at **2.5–3.4k tris each**, gpt-image textures. The user liked the style ("custom olive style") enough to ask for a matching family. He **disliked toon-style trees** (a toon birch and an aspen were rejected) — aim realistic-textured, low-poly silhouette.

Everything is headless Blender **5.1** (run through the kit's `blender` tool, `python .omp/scripts/tool.py blender`) plus Python 3 with `numpy pillow scipy` for textures. Scripts are in `scripts/`; the Unity shader in `unity/`.

| Script | Runs in | Job |
|---|---|---|
| `tree_family_build.py` | Blender | species `CFG` → skeleton → bark tubes → leaf cards → UVs → canopy normals → FBX + .blend |
| `tree_uv.py` | (module) | uniform-texel cylinder UVs for bark, `stretch_stats` |
| `lightmap_uv.py` | Blender (module + CLI) | hand-built `Lightmap` UV (channel 1): bark weighted over leaves per tree, shelf-packed; `LIGHTMAPUV` / `LIGHTMAPOVERLAP` lines |
| `tree_normals.py` | (module) | crown-proxy normal transfer + card winding |
| `tree_finish.py` | Blender | re-run UV/Lightmap UV/normals/export on an existing or hand-edited `.blend` |
| `process_gpt_textures.py` | Python | key generated leaf sheets → RGBA; bark → tileable albedo + normal |
| `branch_atlas.py` | Python | 2×2 leaf-spray atlas with stem base pinned to cell bottom-centre + JSON |
| `check_key_spill.py` | Python | key-colour spill check on every mip |
| `tree_family_textures.py` | Python | fallback textures from CC0 scans (Poly Haven + ambientCG), pre-gpt pass |
| `crown_fullness.py` | Blender (+ numpy/scipy stage) | sky fraction inside the crown silhouette at eye level (`FULLNESS <Sp> sky_mean sky_max`, mask PNG) |
| `bare_limbs.py` | Blender (+ numpy/scipy stage) | bare limb ends/runs outside the leaf mass and floating sprays (painted twig base off the bark) on the packed mesh (`BARELIMBS <Sp> PASS/WARN/FAIL`, renders of each spot) |
| `prompts/*.txt` | — | the exact image-gen prompts used |

## Scale: build for the world's reference avatar
`CFG` `height`/`width`, limb lengths and the Variants are full-size real-world species values. Worlds are
built for people about **1.4 m tall** (WORLD.md reference eye height, default 1.3 m; spatial-design §5.9),
so trees and shrubs are scaled by **k = 0.8** (fixed) before they are placed:
a tree at species height next to the reference avatar reads as oversized. Scale the placed instance
uniformly by k (leaves and bark tile shrink with it, which is intended), or build a world-specific
config with `height`/`width` ×k. Check every tree once beside the reference capsule at the reference
eye height before placing the rest. Paths, decks and walkways under or through a crown still keep the
collision minimums (≥2.3 m clear over walked floors). `crown_fullness.py` keeps its fixed 1.6 m
camera: it is a comparison metric, not a scale.

## Pipeline

```
B="python .omp/scripts/tool.py blender"   # headless Blender from .omp/local/tools.json
# 1 textures (see Textures)
python scripts/process_gpt_textures.py bark bark_src.png TEX/Olive_Bark_Albedo.png TEX/Olive_Bark_Normal.png 3
python scripts/branch_atlas.py TEX/Olive_Leaves_RGBA.png TEX/Olive_Leaves_Cards.json spray_a.png spray_b.png spray_c.png
python scripts/check_key_spill.py TEX/Olive_Leaves_RGBA.png
# 2 build (no LODs by default)
$B --script scripts/tree_family_build.py -- Olive --tex TEX --out Assets/Trees/Olive --blend Source/Olive [--qa qa.png] [--config my_species.py] [--lod1]
# 3 optional: after hand edits in the .blend
$B --blend Source/Olive/Olive_Tree.blend --script scripts/tree_finish.py -- Olive ellipsoid --out Assets/Trees/Olive [--sprig]
```
The build prints `STAT` lines (tris, bounds, bark UV stretch, card attach error, open edges, leaf normal spread) — read them, then render `--qa` and look at it.

### 1. Skeleton (`build_skeleton`)
- `stems=(count, lean, length, r0, r1, gnarl, base_spread)`: trunks fanned around the azimuth, bases spread out (multi-trunk olives 3–6 stems, spread 0.15–0.22 m). `lean_dir`/`lean_fan` = all trunks lean one way.
- `levels=[{n, at, ang, len, r, tip, gnarl, up}]`: children per parent, placed at fractions `at` along it, `ang`° off the parent, radius `r`× parent, `tip` end radius, `up` = phototropism (negative = weeping). `len_scale` 1.6 for olives' long sweeping limbs; `len_taper` shortens higher limbs (cypress).
- **Conifers** (spruce, fir, sugi, hinoki): one straight full-height stem with `taper=True`, `len_taper` ≈ 0.97 (cone), limbs on `levels[0]` with `whorl=k` (k limbs per height, evenly around, each whorl turned at random), `ang_end` (the `ang` range moves to this one from `at[0]` to `at[1]`: 98–112° drooping low limbs, 55–70° rising top ones), `up_end` (the `up` bias ramps to it along each limb: −0.25 = drooping tips), `segs` (limb segments, default 4 / 3; `segs=3` keeps 56 limbs at 1.9k bark). Cards: `sprig` with `mindepth=1`, `upbias` −0.6 (hanging sprays), `size_top` 0.3 (spire), `ground` 0.15.
- **Flat-topped crowns** (umbrella acacia): level key `flat` (0–1, default 0) levels every segment of that level's limbs toward horizontal (`d.z × (1 − flat)` per segment), so the top limbs spread out in one layer instead of rising.
- **Palms / tree ferns / bananas**: `levels=[]` (no branches), `taper=False, caps=True` (trunk keeps its girth, blunt cone under the fronds), `stem_segs` (default 6; 10 for a curved trunk), `bend` (upward pull per stem segment like a limb's `up`; 0.05 with lean 0.4 = leaning coconut curving up). Several stems (banana clump: 4, spread 0.3) each get their own rosette, shorter stems smaller fronds.
- **Bamboo / grass culm clumps** (BoothAssets Bamboo JP1, opt-ins, off = identical builds; checked by geometry hash on JapaneseMaple): `stem_layout=dict(kind="disc", r, gap, rim, lean_min)` (or `kind="ellipse", rx, ry` / `kind="strip", w, d`: a hedge row) scatters the stem bases over an area at least `gap` m apart with its own random sequence instead of the `base_spread` ring (running-bamboo patches, screens); stem 0 (full height) stands in the middle, each stem leans outward from the centre with lean × (`lean_min` … 1 at `rim` m), or with `lean_dir`. `bend_end`: the stem's `bend` ramps to this along it (−0.12 … −0.22: straight culm, nodding/arching tip).
  `stem_layout` `axis_out=a` (m, opt-in, off = identical builds): stems lean out from the centre segment x ∈ [−a, a] instead of the centre point, so a strip fans to both sides along its whole length; with the centre-point lean a strip row leans along its own axis and opens a bare waist in the middle (BoothAssets SasaStrip: `w=2.2, axis_out=0.9`).
- **Dwarf bamboo / groundcover mats** (BoothAssets Sasa JP1): many short straight culms (`stem_segs=1`, `levels=[]`, `stem_layout` disc/strip, rim culms leaning out, `lean_min` 0.15 so the centre stays upright and the mound has no hollow middle), sprig cards `mindepth=0`, `per_tip` 2–3 + the tip card, each card a whole shoot (bare painted culm in its lower third continuing the 3D culm, big leaf fans above), `tilt` 0.5–0.7, `roll_tilt` (20–30, 60): face-up share 0–13 % with good cover from above. Cards on low leaning culms dip their (transparent) lower corners below `ground` 0.07 and get shrunk or skipped (34 culms kept 49 of 102 cards, 6 tips uncovered): use `ground=-0.04` (above the −0.05 skirt). 4-sided culms in the shipped LOD1 (`lod1_sides=(4, 4, 3)`) and a one-band flare (`steps=0`) keep a culm at 24 tris.
- Gnarl uses **deterministic** `noise.noise()` at 3 offsets. `mathutils.noise.noise_vector()` is randomised per Blender session (three runs, three trees) — never use it, or an approved tree can't be rebuilt.
- `seed=None` → `pick_seed()` scores seeds 1–59 for centred crown, target width/height, no twigs below ground.

### 2. Bark mesh (`tube`)
- One tube per branch, ring by ring; sides by depth (`sides=(trunk, inner, deepest)`, default 7 / 5 / 4). **For new trees use `sides=(6, 4, 4)`**: the user wants "4 max 6 sides, very low poly"; smooth shading plus merged joints carry the roundness. `lobe` (0.3–0.36 olive, 0.08 birch/ficus, 0.16 default) wobbles the trunk cross-section for a gnarled base; trunk base ring flattened to z=0.
- `taper=True`: each end narrows to 3 mm over its last 40 %, starting past the last child fork (so child bases never poke out). `caps=True`: 2 cm pointed cone on every end; child bases closed by a cone buried in the parent (apex 1.5 × the child radius back along it, clamped to z ≥ 0: a palm sucker rooted 0.1 m up poked its apex 9 cm under the ground, DatePalmAncient). No open rings, no flat discs. `bury=<k>` (opt-in, default 1.5, off = identical builds) sets that apex depth: a thick limb (r 0.55 × trunk) on a thin lobed 6-sided trunk pokes the 1.5× cone out of the trunk's far side as a strap or faceted wedge that reads as a limb rooted on the trunk surface (BlackPine JP3, review BP6); `bury=0.25` keeps it inside. Level opt-in `root_out=<k>` shifts each limb of that level rigidly k × the parent radius out along its own radial (same shape, no draws), so a thick limb clears the trunk wall within the trunk radius instead of running ~1.2 radii inside it (BlackPine level 0: `root_out` 0.35 with `bury` 0.25).
- **Fork joints: use `merge` on every new tree.** Without it a limb whose last child starts near its end tapers to a spike past the fork while the child starts thick beside it: the user saw "a lot of these weird joints" (spikes, elbows, loose base cones). `merge=dict(at=0.7, ang=50, blend=2, round=1, round_bend=20)` continues each such limb into its best-aligned last child as ONE tube (radius blended over 2 points, the joint corner cut once); a child turning more than `ang` is swung rigidly with its subtree to `ang` first, so hairpins become bends. The child keeps its `Br` (cards, attach check, its own children) but is not meshed. Same tri count or less (olive 1.9k → 1.86k bark at 6/4/4 sides). A chain is meshed with its head's side count, so keep sides low: 6/4/4 (the user's limit is 4–6). Clipping branches crossing each other is fine; don't add geometry to avoid it. `smooth=dict(bend, depth, iters)` (corner-cut whole limbs) and higher `round` roughly +40 % bark tris for little visible gain. Pin `seed` when rebuilding an approved tree (`STAT <name> seed N`).
- The merge drops the limb's stub past the fork, so it is skipped when another child's base hangs on that stub and the merged tube would no longer reach it (`STAT … merges skipped`); with `lod1_subset` a tube whose every-other-ring chord leaves a child's bark floating is meshed at every ring (`STAT … tubes kept at every ring`). Both print only when they fire, so unaffected trees rebuild byte-identical.
- **Child base cones stay inside the parent tube (default `base_clamp`; user: "olives are sticking branches on the other side of the trunk").** The cone that closes a child's base ring (apex 1.5 × the child radius back) and the ring corners on its far side can leave a thin lobed or 4/3-sided parent as light triangular bark wedges opposite the limb (82 of 121 shipped BoothAssets trees had one, up to 6.5 cm outside, and the corrected checker found 49 trees with 176 more cones after the first repair; invisible from the limb's side and to every earlier check). After meshing, `scripts/base_cones.py` `clamp(bm)` finds every child's base cone from the mesh topology, tests the apex, ring corners, ring→apex edge samples **and a barycentric grid inside every cone triangle** (where three equal limbs meet a face can cross the crease with its middle 25 mm out while every edge point is inside) against the union of the other tubes (lobe, sides, taper, merge and declip included), pulls ring corners > 2 mm outside toward the parent axis (capped at 1.5 × the child radius) and slides the apex toward the ring centre until all samples are inside, repeating until a pass moves nothing (`settle`). A child with no wider tube around its base (nodes on a thin twig, equal-radius forks, unconnected-trunk joints) cannot hide its cone, so it is closed flush (apex onto the ring plane). **The test surfaces are built from explicit triangles and the worse of both quad diagonals**: `BVHTree.FromPolygons` splits quads along 1-3 while Blender and Unity draw 0-2, and the first version passed meshes that still showed wedges. Vertex moves only. It prints `STAT <name> base cones clamped N` **only when it fires**, so trees that never poked rebuild geometry-identical (hash-checked on Rosemary, RosemaryYoung, DatePalm, ItalianCypress, PittosporumYoung, MyrtleYoung; a tree that fires gets a new UV2, which is projected from the geometry). `base_clamp=False` restores the old build; `bury` / `root_out` stay for steeper limb roots. Check a packed mesh with BoothAssets `Tools/trees/basecone_check.py` (0 flagged = every sample ≤ 3 mm outside); repair shipped meshes without touching topology, UV0, UV2 or colours with `Tools/trees/basecone_fix.py` + `fbx_compare.py`.
- `flare=dict(r=1.3, h=0.35, skirt=0.05, steps=2)` (opt-in, off = identical builds): every ground-rooted stem (trunks, multi-stem bush stems, palm trunks) widens to r× its radius at z = 0, easing back concavely over h m (capped at 30 % of the stem so short bush stems stay slim); the flare rings tilt from horizontal at the ground to the axis, so leaning stems meet the ground in a round footprint; one skirt ring `skirt` m below ground, closed by a flat disc (no open bottom, no gap on uneven ground). Bark UVs stay continuous (the flared rings keep the plain stem's wraps). Cost per stem ≈ (2·steps + 3) × trunk sides tris (42 at 6 sides; less where a skeleton point already sits at a flare ring). Skirt faces are excluded from the coplanar check; the bounds STAT shows z min −skirt.
  `flare` `skirt_axis=s` (opt-in, off = identical builds; checked by geometry hash on BambooYoung, BlackPineYoung and SasaPatch): the skirt point runs on along the stem's first segment instead of straight down, so a leaning thin stem has no kink at z = 0 where the base is seen without terrain (a Unity close-up of SasaTall showed every culm bending vertical at the ground). `s` = the pack scale the mesh ships at: `tree_booth_pack.py` scales x/y but keeps underground depths, so the horizontal offset is divided by `s` to stay on the axis after packing (BoothAssets SasaTall/SasaStrip: `flare=dict(FLARE, skirt_axis=0.7)`). Min z stays −skirt.

### 3. Canopy cards (`crown`)
Material index 1, quads (or 2-quad V-folded cards, `fold` 0.08–0.1). Modes:
- `sprig` (olives, best result): every card's atlas stem-base point lands **exactly** on a branch axis (`sprig_card` + atlas JSON), every terminal end above `minz` gets a card, then `fill.frac` (≈0.45) of cards on inner limbs leaning to the crown axis to close gaps between clumps. 380–630 cards, size 0.75–0.85 m.
  `flat` (0–1, default 0, sprig only): cards lie toward horizontal and face the sky (card direction `z × (1 − flat)`, roll pulled to up), for thin layered umbrella crowns (Acacia 0.85). Off = identical rebuilds.
  `roll_tilt=(lo, hi)` (degrees, sprig only, opt-in): each card is rolled about its own axis to stand lo–hi off the plane through its axis and the horizontal (overrides `flat`'s face-to-sky roll; flat still levels the direction). Low mats with face-up cards read as flat palm rosettes from standing height, each card showing its spray's 2-D fan (RosemaryProstrate: 51.5 % of leaf area face-up → 0.2 % at (50, 75); `tilt` 0.5 and fill `inward` 0.6 covered the bare centre; seen straight down, cards fanning out of shoot ends still read as soft stars). Own random sequence; off = identical rebuilds.
  `node_step` (m, sprig only, opt-in): cards rooted on ground stems (`mindepth` 0) snap to tier heights every `node_step` m, each stem's tiers phase-shifted (golden ratio); no extra random draws. Bamboo JP1: 0.55 m with `upbias` −2, `tilt` 0.7 (hanging sprays): every culm carries a narrow drooping column of leaf tiers; random sideways sprays on culms read as one round blob on bare stilts. Off = identical rebuilds.
  `surface=dict(c=(x, y, z), rad=(rx, ry, rz), chord=1.0, max_up=None)` (sprig only, opt-in; clipped topiary that must still pass the sprig rules): each card stays rooted on its twig but lies along the level surface of the ellipsoid through its root, facing out, dipped (≤ 40°) so its far end comes back onto that surface; `max_up` (°) rolls it about its axis just enough to stand that far off horizontal (46 → 0 % face-up). `c="root"` (+ `lift`) centres the ellipsoid on each card's own twig root: one dome per twig cluster (cloud-pruned pads). Recipe (BoothAssets IlexCrenata JP1): stems from near the shape centre, 10 twigs each radiating 25–130° off the stem with lengths ≈ the shell radius minus their start distance, `per_tip` 6–7 from `tip_from` 0.5, so twig ends land on the shell and inner cards layer under it; a radial sprig ball (PittosporumBall) reads as a shaggy pompom, the surface ball as a clipped ball. A pure-tangent ball shows ~8 % face-up area; a flat-topped mound needs `max_up`. No extra random draws; off = identical builds.
  `cells=[i, ...]` (crown, sprig/bamboo, opt-in): cards draw only these atlas cells. IlexCrenata JP2: the clipped Cloud/Ball/Mound use a dense, twig-free clipped-surface leaf-patch cell (open sprays tangent on a clipped surface show their painted twigs as a pale web, review C1-jp-ilex BM1); the unclipped Natural keeps the open sprays. Same single random draw per card: off = identical rebuilds.
  `max_rise=<deg>` / `max_fall=<deg>` (crown, sprig, opt-in): a card axis rising more than `max_rise`° above horizontal (or falling more than `max_fall`° below) is clamped to that angle, heading kept, no extra random draws. JapaneseMaple JP2: `max_fall` 40. A vertical hanging card seen edge-on reads as a stippled vertical stripe beside the trunk (review C1-jp-maple JM3). JapaneseMapleLaceleaf JP2: `max_rise` 0, so every card is tip-out or tip-down (weeping mound, willow WW1 rule). Fill opt-ins `up` (default 0.6) and `minz` (default crown `minz`) aim the fill cards (e.g. `inward=1, up=0, minz` near the arch crests: level cards over a bare centre). `tip_upbias_all=True` applies crown `tip_upbias` to every terminal tip card, not only ground stems (Laceleaf 0.6: low drooping twig ends get a level tip card that clears the ground instead of being skipped). `low_tips` opt-ins: `out=(lo, hi)` re-aims the low_tips cards tip-out (radial + own heading, lo–hi° elevation, own random sequence). Off = identical rebuilds.
  `low_tips=dict(min=3, n=7, reach=2.0, size=0.75, ground=0.1, cut=0.8)` (CFG, sprig, opt-in): limbs ending below the leaf zone read as bare spikes at eye height (review finding on OliveAncient/OliveStandard). Every terminal limb chain (a limb plus the children merged into it) carrying fewer than `min` cards gets `n` cards over its outer `reach` m (one at the tip), kept above `ground`. Chains lying entirely below `cut` m with no other branch rooted on them (ground limbs) are not meshed. The cards are added after all others with their own random sequence, so the skeleton and every existing card stay put (checked: pre-fix leaf vertices ⊆ new); only the crown-normal proxy bbox grows a little. Off = identical builds.
- `twig` (maple, birch): cards along depth≥1 twigs above `minz`, pointing outward (`out`) with vertical range `upr` (negative = hanging).
- `ellipsoid` (ficus, stone pine flattened `rad=(2.45,2.45,0.5)`), `spindle` (cypress profile with `peak`). Spindle opt-ins (off = identical builds): `profile="cone"` (clipped topiary cone: rounded base up to `peak`, straight sides to the tip), `shell=(0.7, 1.0)` (radial depth range of the cards, × profile radius), `tangent` (0–1: cards lie up the profile slope and face out, as for `ellipsoid`). BayLaurelCone: `profile="cone", peak=0.03, shell=(0.88, 1.0), tangent=0.6`, proxy `cone`. Ellipsoid opt-ins (off = identical builds): `lumps=dict(amp, size)` (shell radius × 1 + amp·noise over `size` m: a bumpy natural outline instead of a perfect egg), `parts=[dict(c, rad, size=1.0), …]` (several overlapping shells, each card picks one by surface area with its own random sequence; `size` scales that shell's cards: multi-domed crowns, small sucker clumps at the base; the top-level `c`/`rad` are still required, unused). `ground` (spindle/ellipsoid, opt-in): a card reaching below it is lifted until it clears (bushes whose shell sits near the ground). Opaque crowns (bay, cypress): a short visible trunk/stems ending inside the shell, no hidden limbs.
- `twig` / `ellipsoid` / `spindle` map every card to the whole texture; with an atlas set `atlas=True` (or a list of cell indices): each card shows one cell of `<tex>_Leaves_Cards.json`. `tangent` (0–1, `ellipsoid`): cards lie along the shell and face out (clipped topiary: box, Ilex ball); the cards then already face the proxy normal, so `leaf normal |dot|` reads high (0.82 at 0.8) without meaning flat shading.
- `rosette` (coconut, Canary palm, tree fern, banana): fronds radiate from every stem top (terminal end above `minz`). Each frond is a strip of `segs` (4–5) quads along a drooping arc, two per segment with `fold` (edges hang below the midrib); the atlas cell's attach point (bottom-centre, as for sprigs) sits on the stem axis, the cell top is the frond tip, so `attach` and `tips_uncovered` are checked as for sprigs. Per stem `count` fronds on a golden-angle spiral (or interleaved over `spread`°), age 0 = youngest (top, upright) → 1 = oldest (`zone` m lower). `tilt=(old, young)`° above horizontal at the base, `droop=(young, old)`° bent down by the tip (∝ s^`droop_pow`), ± `jitter`°; `length` m range, × (stem length / longest)^`stem_scale` 0.7; `twist`° roll by the tip; `top` m below the stem end; `upright` 0.6 = crown axis between the stem's end direction and vertical; `crop` = share of the cell width meshed (centred on the attach), `aspect` < 1 narrows the frond (squeezes the texture); `cells` = live cell indices. `young=dict(n, tilt, droop, length)` upright spears; `dead=dict(n, tilt, droop, length, cell, zone)` hanging dead fronds (own atlas cell) on the trunk below the crown. A frond that would reach the ground loses droop (× 0.8 per try) until its midrib clears 0.1 m **and** its edges (width, fold hang, twist) clear z = 0; before the edge check a wide low frond could pass with its edges 8–15 cm under the ground (CanaryPalmYoung), and lowering `droop`/`zone` in the config moved the low point around without fixing it. Fronds already above ground build identically; one still under after 12 tries is dropped (FanPalmAncient: 1 low fan of 217). ~800 tris for a 28-frond coconut. With `lod1_subset` the LOD1 fronds stay identical, folded (unfolding moved a coconut's silhouette 10 cm p95); only the old rebuilt LOD1 unfolds them. Textures: one frond per cell, stem at the exact bottom centre, tip at the top, fanned to fill the cell (`aspect` narrows it back).
  Suckers (offshoots at a palm's base): `side=[dict(n, z=(0.1, 0.45), len, ang=(18, 32), r=0.6, tip=0.85, …)]` limbs low on the trunk; each is its own head (keep its top above `minz`·0.8). Frond length and count both scale by `sc` = (head / tallest)^`stem_scale`; a lower `stem_scale` (≈0.3) keeps sucker fronds a realistic 1.5–2 m, and opt-in `head_pow` (≈2.5) makes small heads' frond, `young` and `dead` counts × sc^`head_pow` and their `zone` × sc, so suckers stay cheap (off = identical builds).
`UVMap` (channel 0) = textures; `Lightmap` (channel 1) = lightmaps, laid by `lightmap_uv.repack` (section 4b). Never Smart UV Project.

### 4. Bark UVs (`tree_uv.cylinder_uvs`)
V = arc length / `TILE` (0.6 m per texture repeat), U = ring circumference / TILE; thick rings snap to whole wraps so the seam closes. Gives uniform texel density from trunk to twig (measured `stretch max/min` 1.2–2.1).

### 4b. Lightmap UV (`lightmap_uv.py`): bark gets its own budget
**The transparency trap.** An area-weighted unwrap (Smart UV Project, Unity's Generate Lightmap UVs) sizes each chart by 3D surface area and ignores alpha. Every leaf card is a full quad, transparent corners included, and a crown has thousands, so leaves take ~97 % of the area (bark 2–5 %). Smart UV also cuts every face of a tube into its own chart. Result: 92–96 % of bark charts were under 4 lightmap texels (median ~1). A 1-texel limb bakes one irradiance sample and reads **evenly black or bright against its trunk, with a hard line at every fork** (the fork is a chart border). Stitching can't fix it; texels do.

`repack(ob, bark=…)` lays channel 1 (`Lightmap`) from the UVMap charts:
- one chart per limb chain (the `cylinder_uvs` ribbon) and one per leaf card;
- each chart made isotropic in metres (per-chart u/v stretch from its triangles, so a bark column squeezed into the atlas still gets texels *around* the limb);
- uniform density per m², bark × `bark` (linear) over the leaves;
- shelf-packed into the unit square with one scale found by bisection; margins 0.010 for bark and leaves (0.002 bled neighbour charts into every leaf rim).

Only channel 1 changes, and it is deterministic from the UVMap, so re-running on the same mesh gives the same layout. The builder and `tree_finish.py` call it (CFG `lightmap_bark`, default 5). **Run it again on the mesh that ships, after every geometry step** (card cull, LOD thinning, base-cone clamp, 0.7 pack scale is fine):
`$B --blend <Sp>_Booth.blend --script scripts/lightmap_uv.py -- <Sp>_Tree --auto --ref 5 --fbx <pack>/<Sp>_Tree.fbx --save`.
- **Per-tree weight (`--auto`, `choose_bark`):** the smallest bark weight that gives the p10 limb ≥ 2 texels around (`--around`) and the trunk ≥ 8 (`--trunk`) at the reference resolution `--ref` texels/unit with Scale In Lightmap 1. It is capped so leaves keep ≥ `--leaf-floor` × ref texels/m (default 0.5). Prints `LIGHTMAPAUTO <ob> bark xN targets MET | SHORT (leaf floor)`. A SHORT tree is reported, not patched with lightmap scale.
- **The texel figures are a prediction.** They assume the lightmapper sizes an instance so its mean density equals the scene's texels/unit. A Bakery bake measured ~0.57× the predicted absolute density, with the bark:leaf ratio exact. Prove it on a test bake.
- **Ship it in the FBX.** The asset can't store a lightmap scale, so the whole fix lives in the UV. Prefabs keep Scale In Lightmap 1. Unity's Generate Lightmap UVs stays off (on, it throws this layout away).
- Measured (ref 5, auto): HolmOak bark ×4.0, fill 0.58, bark 15.4 / leaf 3.9 texels/m, p10 limb 2.5 and trunk 8.0 texels around. OliveVase hit the leaf floor at ×6.3 (limb 1.8 texels around), so thin-limbed olives need ref ≥ 6 or a lower floor.

## Canopy normals (crown-proxy transfer)
**Why:** leaf cards are flat alpha-cutout planes at random positions/orientations. With their own face normals each card catches light independently → a flat, noisy, obviously-card canopy (bright/dark speckle, cards flash as you walk around). Giving every leaf vertex the normal of a **smooth volume shaped like the crown** makes the whole canopy shade as one soft lit mass (lit side / terminator / shadow side) while the alpha keeps the leafy silhouette. Bark keeps its own normals.

**Before/after metric** (`leaf_normal_spread`, mean |dot(loop normal, face normal)|): 1.0 = flat cards; measured after transfer olive 0.45, cypress 0.59–0.63.

**Implementation (`tree_normals.transfer_crown_normals(ob, kind, inflate=1.05)`):**
1. `align_card_winding`: flip every card whose front faces into the crown (BVH nearest point on the proxy), else back-face-flipping shaders/Cycles turn half the cards' normals inward → near-black crown.
2. Proxy is fitted to the **leaf-vertex bounding box**: centre = bbox centre, half-extents = bbox half-size, × `inflate` 1.05. No separate centre offset or face-normal blend parameter exists (no blend = 100 % proxy normal).
3. `ellipsoid` / `capsule` → **analytic**: per leaf loop `n = normalize((p−c).x/rx², (p−c).y/ry², (p−c).z/rz²)` (ellipsoid gradient; for a sphere that's `normalize(p − c)`), written with `me.normals_split_custom_set(loops)`. `cone` → analytic too (formula in the table below; `cluster` works with it); no proxy mesh, `align_card_winding` takes the same normal function.
4. `hull` → icosphere shrink-wrapped (nearest surface point) onto the convex hull of leaf verts, Smooth ×8 at factor 1, inflated; then a **Data Transfer** modifier on the tree: loop data `CUSTOM_NORMAL`, mapping `POLYINTERP_NEAREST` (nearest face, interpolated), vertex group = leaf verts only, mix REPLACE 1.0 — **applied** (`modifier_apply`).
5. All faces set `use_smooth=True` (Blender 4.1+/5.x has no auto-smooth toggle; custom split normals just need smooth faces). Normals are baked into the mesh before export; FBX writes them.

**Which proxy per crown shape** (`proxy=` in CFG):
| Crown | Proxy | Used for |
|---|---|---|
| round / ball | `ellipsoid` (bbox-fitted; sphere if equal extents) | olives, ficus, single birch |
| columnar | `capsule` (tall ellipsoid, same analytic code) | Italian cypress |
| umbrella / flat-top | `ellipsoid` — the bbox fit squashes it automatically (z-extent small) | stone pine, acacia |
| clumpy / irregular | `hull` (shrink-wrapped smoothed hull) | Japanese maple, birch clump, weeping birch |
| conical (fir/spruce, sugi, hinoki) | `cone` — analytic: apex at the top of the leaf bbox, base = its half-extents; n = normalize(radial·cos α + up·sin α), α = atan(R/H) the half-angle, radial = the ellipse gradient; the card winding uses the same normal (no proxy mesh) | test spruce: spread 0.38–0.49 |
| rosette (palms, tree fern, banana) | `ellipsoid` around the fronds: tops shade up, drooping tips out/down; dead fronds lower the bbox centre a little | test coconut 0.51, banana clump 0.33–0.36 |
| weeping (willow) | `hull` already follows drooping sides; or an ellipsoid with lowered centre | weeping birch |
| multi-clump | not built yet: one proxy per clump (cluster leaf verts, fit each), assign each leaf vert the nearest clump's normal, blend near borders | — |

**Unity side:** FBX import **Normals: Import** (`normalImportMode: 0`), not Calculate — Calculate throws the transfer away. The two-sided shader must NOT flip these normals on back faces: keep **`_UseMeshNormalsBothSides = 1`** on `unity/SoftCrown.shader` (the default) for canopy-normal leaves; flipping via `VFACE` makes the crown patchy.

## Textures
**Leaves** (`prompts/olive_leaves_top.txt` is the approved one): botanical flat-lay, straight down, flat overcast light, no shadows, background **one uniform flat magenta #FF00FF** (chroma green #00FF00 for red/purple foliage like Japanese maple), ONE spray of 5–7 twigs fanning up from a single stem entering at the **exact bottom centre**, fills ~90 %, light overlap, upper leaf surfaces only (no silver undersides/flowers/fruit). Generate 3 variants (a/b/c).
- `process_gpt_textures.leaf(src, dst, key, soft=True)`: keyness = min(R,B)−G (magenta), threshold from border median ×0.45, soft alpha ramp, opening + speck removal (<60 px) + 1 px erosion, despill, then **colour of every non-opaque texel = nearest opaque core texel** (distance-transform dilation) so no mip shows key colour. `triple` = 3 plumes side by side for narrow sprays (cypress).
- **Flowers: pick a key far from both petals and leaves**, and add `--edge-despill`. The default despill subtracts the key from *every* pixel, and keyness above ~0.3×threshold falls into the soft ramp: on magenta, pink/purple petals go dull and semi-transparent; on green, green leaves go grey. `--edge-despill` (`edge_despill=4`) despills only the opaque 4 px band inside the matte edge, where spill actually is. Measured: pink/purple + green (lilac, oleander) → **cyan #00FFFF**; pink azalea → blue #0000FF; blue/purple hydrangea → yellow #FFFF00 (keys out yellow-green young leaves: check); red (hibiscus, camellia) and white keep magenta, default despill. Leaves-only sprays in the set (e.g. 1 of 3) stop a flowering bush reading as solid colour.
- **Thin needles: shoot green needles on blue #0000FF** (`--key blue`; magenta blends into needle tips as a pink/tan fringe no despill removes); blue-green needles that must stay on magenta get `branch_atlas.py --defringe` (despill residue recoloured from clean texels).
- `branch_atlas.py`: 2048² atlas, 4 cells of 1024² by default, each spray uniformly scaled so its stem centroid (bottom 3 opaque rows) sits on the cell's bottom-centre, 16 px margin; JSON `{"cells":[{"rect":[u0,v0,u1,v1],"attach":[u,v]}]}` feeds `sprig` mode. `--key magenta|green|cyan|blue|yellow`, `--edge-despill`. Expect `stem_offset_px_after` ≈ 0, `border_alpha…` = 0.
- `branch_atlas.py --layout <json>`: custom cells in image pixels, `{"size": 2048, "cells": [[x, y, w, h], …]}` (any aspect; e.g. four 3:4 portrait cells 768×1016 beside a 512 px bark strip for a one-texture tree atlas whose bark repeats in V). The JSON output keeps `"layout"`. `sprig_card`/`card` make each card as wide as length × cell w/h, so the spray is never stretched: generate sprays at the cell's aspect (3:4 portrait sprays for 3:4 cells). Square cells build identically to before.
- **Thick trunks on the column atlas:** repeat the bark an even number of times around rings over ~0.9 m girth, mirrored (no seam); otherwise one texture width smears around a 4–5 m trunk. Check a close-up of the thickest packed trunk.
- `process_gpt_textures.leaf()` scales the source to 2048 px wide and keeps its aspect (a 3:4 spray stays 3:4; it used to be squashed to 2048²).
- `check_key_spill.py --key <the key used>`: per box-filtered mip, `<key>_px` must be **0** (edge spill ≤ ~50/255 was accepted). The magenta band also counts pink/purple petals and the green band saturated leaves, so check with the key the sprays were shot on, and look at the atlas over grey.
**Bark** (`prompts/*_bark*.txt`): seamless orthographic unrolled bark, flat light, trunk vertical. `process_gpt_textures.py bark src albedo normal <strength>`: half-offset edge-blend tileable, 1024², OpenGL normal from blurred luminance (strength ~2–4).
Names the builder expects: `<tex>_Bark_Albedo.png`, `<tex>_Bark_Normal.png`, `<tex>_Leaves_RGBA.png`, `<tex>_Leaves_Cards.json`. Variants can share one texture set via `tex=`.

## Full crowns (current standard)
Users judge trees too "branchy and less full" when sky shows through the whole crown: the earlier family (olives 0.34–0.50 sky inside the crown, holm oak 0.27) was sent back for it. A realistic tree reads as continuous foliage masses with branches hidden, sky only at the edges and in a few gaps. Rules:
- **Measure it.** `crown_fullness.py` on the shipped (culled) mesh: perspective camera at 1.6 m eye height, 2× crown width away, 4 azimuths, alpha cutout 0.45, bark opaque; silhouette = coverage closed by 0.6 m with holes filled, above the lowest leaf; sky = 1 − covered/silhouette. Report mean and max. Targets: dense species (cypress, carob, bay, holm oak, juniper, shrubs) ≤ 0.15; cedar ≤ 0.20; open species (olive, Aleppo/stone pine, fig, palms) ≤ 0.30. Measured after this standard: cypress 0.03–0.07, carob 0.04–0.07, myrtle 0.08–0.10, fig 0.11–0.13, holm oak 0.12–0.15, pines 0.10–0.24, olives 0.20–0.29.
- **Bigger cards, not denser sprays.** Never regenerate the sprays as dense foliage clumps or add overlapping cards to fill a crown: a rebuild that took olive cells from ~0.23 to ~0.5 coverage and added cards measured fuller (sky 0.41 → 0.20–0.28) but read as stacked textures, and the user rejected it ("not actually fuller just overlapping textures, never do this"). Instead draw each spray as a **bigger open branch section with smaller leaves** (olive: 10–14 twigs, 90–110 leaves each ~1/16 of the image height instead of 35–45 at 1/10; "open and airy, NOT a dense clump"; cells stay ~20–25 % opaque) and scale the cards up by the same factor (`size` × 1.6), so leaves keep their real size while every card covers more crown. Olives went from sky 0.30–0.41 to 0.20–0.28 with the same card counts and the user confirmed they "look better".
- **Every visible spray grows out of a 3D twig (`sprig` mode).** Each card's painted stem base is pinned on a bark twig (`sprig_card`), so the PNG branch visibly continues a modelled one; `attach out_of_tolerance 0`, `tips_uncovered 0`, and no bare limb end or bare limb run outside the leaves (`scripts/bare_limbs.py`). The user: "oaks are properly built with transparent png branches actually going out of a 3d branch". **Only exception: a crown so thick that no trunk or limb inside it can be seen from any angle** (Italian cypress column, clipped topiary balls/blocks): there `spindle`/`ellipsoid` volume crowns with only the visible trunk and root flare are allowed (cypress: 84 bark tris). Do not use volume crowns on open or dome trees: carob, cork oak, bay laurel, myrtle and Phoenician juniper built that way showed floating sprays and bare limb spikes once their sprays were opened up. `tips_uncovered`/`attach` print `None` in volume modes, so the build checks silently don't cover them. Crown width from a spindle ≈ 2 × (`rmax` + 0.6 × card size); for ellipsoids read the bounds STAT after one build and correct `rad`.
- **Open species keep their structure** (olive, fig, pittosporum mound, pines, cedar tiers): bigger cards with small-leaf branch sprays, drop the inner twig level, `low_tips` on bare limb ends; the visible limbs are what identifies the species.
- **Card size vs leaf size.** Enlarging cards alone enlarges the leaves; shrink the leaves in the spray by the same factor (prompt leaf height as a fraction of the image) so leaves stay real size.
- **Check leaf size by hand too.** `leaf_size.py` reads overlapping leaves as a few big ones and skips `spindle`/`ellipsoid` trees; on small-leaf sprays it read 7–8.5 cm where a hand count gave ~9.5 cm. Measure leaf px on a grid in 2 cells × card length / cell px.
- **Bigger cards stretch edge-on streaks** (dotted lines 0.5–1.5 m past the crown): fade leaf alpha in the shader as the card turns edge-on, using |cos| between the view and the true face normal from `cross(ddy(worldPos), ddx(worldPos))` (the mesh normals are the crown proxy's), forward passes only so shadows and bakes keep the leaves. Small-leaf branch prompt: `scripts/prompts/olive_branch_small_leaves.txt`.
- **The card cull rarely passes on dense volumes**: even frac 0.05 moved cypress silhouettes 2–22 cm against the 0.3 cm allowance. Plan an unculled card count inside the budget; on branch-structured trees 0.10–0.20 still passes. **The cull must never bare a limb end**: a card no orthographic view sees can still be the only leaves on a limb tip seen from under the tree (HolmOak lost 5 limb-end covers, 1–1.9 m bare). `lod1_cull_cards.py` (BoothAssets `Tools/trees`) has an always-on tip guard: every bark tube end above 0.6 m keeps a card whose painted twig base lies within 0.15 m of it (the nearest one within 0.35 m stays when the threshold would drop them all; `CULLED … tip_guard kept N`, 2–12 cards on the test trees, +4–24 tris).
- **Volume crown → `sprig`:** the first skeleton comes out 1.2–1.7× too wide (shorten limbs, not cards) and fringe sky rises 0.01–0.04; that's expected.
- **Cull:** keep a fraction only if the packed tree still passes `bare_limbs.py`.
- **Bare low limbs / leaders:** `minz` below the lowest leafy limb; `tip_from` ≈ 0.05 on bare leaders; children over 0.3–0.9 of a limb, not at its end.
- **Trunk visible through a tiered crown:** `crown.fill` 0.2–0.3 (cards on inner limbs, angled back and up).
- **Ground:** place leaf cards ≥ 0.07 m up; the bark snap moves them a few cm afterwards.
- **Mat shrubs:** stems on a small ring, uneven and curving, side shoots arching over the centre; one root point reads as a starburst.
- **Italian cypress:** height:width 6–8.5 (slim ≤ 10); foliage tapers to a soft point over the top 15–20 %, nothing poking above.

## Tri budgets (measured)
LOD0 2.5–3.4k (olive 3.3k: 1.8k bark + 1.5k leaf; cypress 2.6k: 0.6k + 2.0k). Optional LOD1 0.7–1k. Compare: the stock trees they replaced were 15–16k each. Full-crown packs (shipped LOD1): trees 1.9–3.4k, young trees 0.7–2.8k, shrubs 0.5–1.7k.

**Machine load.** Each headless Blender uses every core by default; two at once plus a dozen agent sessions froze a 16-thread workstation. `tool.py blender` caps concurrent Blender runs machine-wide (`blender.max_parallel`, re-read while queued) at `blender.threads` each, below-normal priority (`.omp/local/tools.json`). **Never let jobs queue:** run only as many Blender-using agents as there are slots (+1 at most), each with one Blender job at a time; pause the rest (they generate textures and write configs) and send GO as a slot frees. Eleven agents queuing 15 jobs behind one slot looked stuck to the owner for two hours. Test at most 3 cull fracs per tree.

**LODs: off by default.** In worlds under ~300 m across trees are always seen at LOD0 range, so a LOD1 + LODGroup is only extra memory and bake/probe complexity (Bakery skips LODGroup renderers without per-LOD setup). Use `--lod1` (exports `_Tree_LOD0`/`_LOD1` in one FBX: 5/4/3 sides, half the deepest twigs, 60 % cards at 1.35× size, unfolded) only for very large worlds, then add a LODGroup. That rebuilt LOD1 re-scatters every card and pops. Prefer `lod1_subset=dict(keep=1.0, grow=1.0)` with `lod1_sides=(6, 4, 3)`: LOD1 = LOD0 with every card in place and lighter bark (every other ring), 20–45 % fewer tris, silhouette within 4–8 cm (p95). The every-other-ring chords leave cards rooted between kept rings hanging 5–46 cm off the thinner tube (bare_limbs floating: WeepingWillow 10 %, CedarOfLebanon 3.5 %), so every LOD moves each card whose attach point lies farther than the tube radius from the meshed axis rigidly onto it (`snap_cards_to_bark`, always on, 0 tris; floating 0 % after; cards within the radius never move, `STAT … cards moved onto the meshed bark` only prints when it fires). Thinning the cards does not pay: `keep=0.5, grow=1.3` moved the silhouette 18–20 cm and `keep=0.5, grow=1.0` left 10–25 cm holes. Switch heights follow the kit LOD rule (vrchat-world-optimization `references/room-lods.md`): a level switches in where its measured error is about one pixel (0.0015 rad, lodBias 1, 110° FOV), h = size / (2 d tan 55°) with d = error / 0.0015; never Unity's default heights.

## Big trees around walkways (treehouse, 2026-10)
Giant jungle trees (70–100 m, crowns r 12–28 m, houses inside the crown) use the same builder plus optional CFG keys (all off by default):
- `clear=[dict(poly=[(x,y)…], z=(z0,z1), margin=m) | dict(seg=((x,y,z),(x,y,z)), r=m)]`: keep-out volumes (deck prisms, stair/bridge capsules). Limbs never start inside one, stop `clear_pad` m before entering one (segment midpoints are tested too), and cards are rerouted, then shrunk, then skipped. A card is tested along its axis and at its corners (±width/2 at base, 35/70/100 %). A skipped tip card counts as `tips_uncovered`; a few (≤ 4 of 100+) next to decks are expected.
- `side=[dict(n, z=(lo,hi), len, ang, r, tip, gnarl, up)]`: extra trunk limbs at absolute heights, without children (dead stubs low down; leafy secondary limbs get one tip card above `minz·0.8`).
- `buttress=dict(n, z, reach, r)`: flaring roots from the lower trunk out and down to z = 0. Only where the trunk base is visible on dry ground; in flooded worlds the base is under water, so leave it off ("roots are submerged trees are sticking out of the water").
- `vines=dict(count, size, z)`: hanging sprig cards under depth ≥ 1 branches (draped foliage/epiphytes), rooted on the axis like sprigs.
- `bark_tile` (0.6): metres per bark repeat; on 2–6 m trunks use 2–3 m per repeat, scaled by trunk radius (`bark_tile_r`, `bark_tile_min`), plus a large-scale tint/moss macro variation (`bark_macro`) and a per-tree UV offset. A scan with distinct single knots grids up visibly ("bark is too repeated"): pick one with even, ridged texture.
- `lod1_cards` / `lod1_size` (0.6 / 1.35): LOD1 card share and size, e.g. 0.24 / 1.8 for ≤ 2k LOD1 on a 7k LOD0.
Per-tree configs can be generated from a layout file (one species per tree, volumes in tree-local coordinates; FBX maps Blender (x,y,z) to Unity (−x,z,−y), so place at rotation 0). Example: a per-world layout script such as `<project>/Blender/trees/<world>_trees.py`, checked with `verify_tree.py` (exact z-fight pairs, vertices inside walk volumes, crown floor). Measured (treehouse world): 10.3–21.0k tris per village kapok (2.6–10.4k bark, 6.4–13.1k leaf), ring trees 6.2–6.7k with LOD1 1.8–1.9k.
For night worlds grade the leaf atlas once (a per-world `grade_atlas.py` next to the layout script: soft shoulder on linear luminance, knee 0.07 → max 0.20): gpt leaf sprays carry glossy highlights that render near-white under torches.

## Realistic trees: checklist
1. Crowns grow from the branches; blockout spheres are placeholders, never leaf targets.
2. Many long medium branches; leaves only near branch ends. Check a leaves-hidden render.
3. Full crowns (see "Full crowns"): foliage masses, branches hidden, sky only at edges and small gaps; open species keep their visible limbs.
4. Real leaf size, measured against the avatar (kapok leaflet 8–20 cm, fig 15–25 cm).
5. One leaf branch per atlas cell, little overlap (olive method).
6. One natural green; vary leaf type between trees, not colour.
7. Leaves matte (smoothness 0); per-cluster normals on giants.
8. Obey the setting (no roots under water); compare with the user's reference photos.
9. Twigs in the leaf sprays are the same wood as the bark texture: generated sprays often come out with red/pink twigs. Fix with `image-edit` (spray first, bark second as `--reference`; prompt: repaint only the wood to match the bark, keep everything else and the key background), then rebuild the atlas; a hex colour sampled from the bark helps when the first edit stays reddish.
10. Leaves only: flowers, fruit, berries, cones and buds on flat alpha cards look bad (user rejected a whole flowering set), so prompts say "leaves only, NO flowers, NO fruit, NO berries, NO seeds, NO catkins, NO cones, NO buds" and every spray is inspected. Species valued for their blossom don't fit this method.
11. Generated sprays draw leaves 2–3× too big for the card (the commonest review finding). Ask for many small leaves ("about 25–35 small leaves, each about 1/12 of the image height"), and measure leaf length = leaf px / cell px × card size against the species' real range.
12. Bare limb ends below the leaf zone read as dead spikes at eye height and `tips_uncovered` misses them: use `low_tips`.
13. A crown that needs to look fuller gets **bigger cards** (`size`), never denser spray textures or more overlapping cards: dense-clump sprays (~50 % opaque cells) plus extra cards read as stacked textures, not a fuller tree (user rejected an olive rebuild done that way: "never do this").

## Unity setup
- FBX: Scale 1, **Normals Import**, Generate Lightmap UVs **off** (the `Lightmap` channel comes from Blender; on, Unity replaces it with an area-weighted unwrap), Add Colliders off, Read/Write off, mesh compression off. Materials extracted/assigned manually.
- **Shader: `unity/SoftCrown.shader`** (Built-in RP surface shader). One material for the whole tree when bark and leaves share one atlas (`scripts/tree_atlas.py <tex_dir> <Tex> --layout column`, cells from `scripts/layouts/column_4cells.json` via `branch_atlas.py --layout`): bark is the column at u ≥ `_BarkU0` 0.76 and never clips. For a separate leaf material on a leaves-only atlas set `_AtlasLayout` 0 (bark stays on Standard). The defaults are the recommended settings: Cull Off, explicit `clip()` (the `alphatest` pragma blended leaves against bright HDR backgrounds and burned them white), addshadow + meta pass so bakes use the leaf silhouette, RenderType TransparentCutout, `_Cutoff` 0.45, leaf smoothness 0 (glossy leaves rim against the sky), `_UseMeshNormalsBothSides` 1, `_EdgeFade` 1, alpha to coverage on with the far-only anti-shimmer (`_LeafMipBias` 0.35, `_A2CFarCutoffDrop` 0.05).
- **Wind**: SoftCrown's `_WIND_ON` (port of Silent's Crispy Foliage wind: gusty terrain-grass wave + leaf tremble, world space so static batching keeps it) reads its weights from the vertex colour, written by `scripts/tree_wind_data.py` (`write_wind(ob)` before FBX export; R tree height / 32 m, G tremble, B tremble phase, A gust weight). Meshes without vertex colours stay still. Meta pass has no wind (bakes at rest pose). Edit-mode time is frozen, so judge wind in Play mode or set `_Time` per frame with a camera CommandBuffer.
- **Leaf cards passing through each other in the wind** (measured by simulating the shader on the shipped meshes: point pairs on different cards within 6 cm, does one cross the other's plane): the per-card random phase is a minor cause. The big ones: (1) any spatial frequency in the wind comparable to a card's size (Crispy's tremble phase `2.65·(x+y+z)` is a 1.4 m wave; gust wave size 1 on tall trees), because a card is 1–2 big triangles and two crossing cards interpolate the field from different corners; (2) per-card weights (tremble × card length, a card's own stem value as gust weight). Make every weight a function of position (G from the distance to the nearest stem edge or bark, B a 3 m value noise, A a local mean of stem heights) and keep the fields slow (tremble phase 0.5 rad/m, wave size 0.5): pass-through deeper than 2 cm drops 7–13× at strong wind with the same overall motion. Exact Crispy (tremble weighted by the pinning mask, bark trembling too) helped little and lifted card bases 4–6 cm off their branches.
- **Bushes "breathing" (growing and shrinking) after making the tremble coherent**: leaf normals are crown gradients (radial), so a tremble along the normal with one shared phase over a 1–2 m crown is a coherent in/out mode (silhouette area ±6–7 % std at strong wind). Tremble small plants sideways instead (shared horizontal direction, wind turned ±90° by a smooth noise; SoftCrown does it below 3 m tree height from vertex R, blending to the normal by 6 m): silhouette std 0.4–1.5 %, pass-through unchanged. Keep the normal on tall trees: a sideways tremble roughly doubles their card pass-through, and 1 cm of in/out on a 4 m crown doesn't read. Measure crown size as silhouette pixel area per frame from a fixed camera with a flat clear colour.
- Leaf texture: Alpha Is Transparency on, **Mip Maps Preserve Coverage on, alpha reference 0.45** (= cutoff, so the crown doesn't thin out in the distance), max 2048, Clamp, **Trilinear** filtering (bilinear shows mip steps on quality levels that don't force trilinear).
- **VR leaf shimmer.** Leaves ~1 px wide at 6–40 m sparkle as the head turns, and the sparkle covers the whole crown interior, not only its outline. MSAA alone does nothing for a `clip()` cutout, alpha to coverage alone helps ~8 %, and a global mip bias blurs near leaves (bias 2 turns blobby). What worked (A2C on, at VRChat's default MSAA 4×): in the leaf path compute `lod` from `ddx/ddy(uv)` × texel size and `far = saturate(lod − 1)`; sample with `tex2Dgrad(uv, dx·g, dy·g)` where `g = exp2(0.35·far)`; on the A2C path use cutoff `_Cutoff − 0.05·far`; shadow and meta passes keep the plain cutoff. That cut flicker above a 4× supersampled reference ~45–70 % at 6–40 m with coverage within 1 point and foreground leaves unchanged. Bias 0.75 clumped far sprays into dark lumps, A2C without the drop thinned far crowns ~10 %, drop 0.1 overfilled them. A2C's 4-level dither raises edge crawl (still under half of Crispy Foliage's).
- **Judge shimmer in the Game view or a headset, never the Scene view**: the Scene view renders 1 sample per pixel regardless of quality settings, so A2C does nothing there. Measure on a pure camera yaw of 0.25 px per frame: flicker = mean |next(x) − (0.75·this(x) + 0.25·this(x−1))| over the crown, frame to frame, against a 4× supersampled + MSAA 8 render of the same view; coverage from black- and white-clear renders of the tree alone (alpha = 1 − (white − black)).
- **No colliders** on trees (walk-through; add one thin BoxCollider on the trunk only if the world needs it). No seat stations.
- Static: one renderer holds bark + leaves → mark Contribute GI / lightmap static (+ Reflection Probe Static); leaves are **lightmapped, not probe-lit**. Scale In Lightmap 1 by default (bark resolution comes from the `Lightmap` UV); raise it only per scene for near-camera hero trees.
- One-atlas column trees on a third-party foliage shader (e.g. Silent's Crispy Foliage): Cull Off, no back-face normal flip, vertex-colour tint/occlusion intensities 0 when the vertex colours carry wind data, and "fade at glancing angles" on, which removes the streaks of edge-on cards within ~1 m.
- A custom cutout shader must tag its SubShader `"RenderType"="TransparentCutout"`: tagged `Opaque`, the Progressive lightmapper bakes every leaf card as a solid rectangle shadow.
- Probe-lit trees swapped in over old ones go dark on the upward-facing leaves: the probes were baked with the old crowns shading them. Re-bake, or temporarily soften the probes' directional term.

## Lighting gotchas
- **Tree uplights:** a narrow cone hugging the trunk lights only the trunk up to the first fork — the lightmapped leaves receive ≈0 (bark occludes them). Place ground uplights **1.75–2 m out** from the trunk on the viewer side (path/building), aim at the **LOD0 bounds centre** (tilt ≈35–37°), 60° cone, inner 40 %; then tune intensity until lit leaves read (a modelled mean ≈0.12 on the leaves needed intensities 9.5–15.75 in a night scene).
- A wrong winding/normal flip shows as a near-black or patchy crown: re-check `align_card_winding` and `_UseMeshNormalsBothSides`.
- After any lighting bake, rebake reflection probes.

## Verify before calling it done
`STAT` tris in budget, `open_bark_edges_above_ground 0`, `floating_bark_components 0` (every LOD; bark islands not connected to the ground-rooted bark, `tree_checks.py` also checks saved blends), `tips_uncovered 0`, `attach LOD0/LOD1 … out_of_tolerance 0` (measured against the tubes actually meshed in that LOD, i.e. the shipped thinned LOD1 bark), bark stretch max/min ≲ 3, leaf normal spread < 0.7, on the shipped mesh `LIGHTMAPOVERLAP … overlapped 0` and `LIGHTMAPAUTO … MET`, the FBX reading back with UV layers `['UVMap', 'Lightmap']`; `--qa` render; in Unity a composition review from eye height and from below at night, plus a test bake with limbs lit continuously with their trunk.

### Bare limbs and floating sprays (`bare_limbs.py`): run on every tree before packing ships it
`tips_uncovered` only counts terminal ends of the skeleton that got no card; it never sees a thick limb or stem that tapers to a bare point under or beside the crown (BayLaurelAncient: 4 grey stem spikes, CorkOakAncient: three 5 m limbs ending in bare points), nor cards whose painted twig hangs in the air (volume crowns). Run
`$B --script scripts/bare_limbs.py -- --out <qa dir> [--render] Source/<Family>/<Sp>/<Sp>_Booth.blend …` (also takes a culled `_Tree.blend`). It measures the shipped mesh with only the opaque texels as leaves: **bare end** = a limb tip above 0.6 m with no leaf mass within 0.35 m (leaves in < 50 % of directions) and no painted twig attached, fails at ≥ 0.25 m bare; **bare run** = > 1 m of limb above 1 m with no leaf mass within 0.6 m (trunk and scaffold limbs under the canopy that lead on into leaves are exempt); **floating** = card whose painted twig base (read from the atlas pixels) sits more than max(5 cm, 2 twig radii) off the bark (sprig trees: oaks measure −6…+5 cm; fail above 2 % of cards). Spots deep inside the crown (leaves within 1.5 m in ≥ 75 % of directions) only WARN, they show from under the tree. `ends_covered_in_lod0` = ends the hidden-card cull bared (cards present at LOD0). Need: `PASS`, or `WARN` with a look at the from-below render. Volume crowns (`spindle`/`ellipsoid`, < 50 % attached cards) report floating by design and must pass the bare checks, i.e. hide all wood.
