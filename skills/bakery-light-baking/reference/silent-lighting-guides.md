# Silent lighting guides + Bakery manual: operational notes

Source-review date: **2026-09-12**. Documentation research only; no Unity scene, installed package, shader, headset, or bake was tested for this review. These are third-party recommendations, not personal user preferences. Existing scene-specific measurements and scripted recipes remain in `../SKILL.md` and `examples.md`.

## Sources and coverage

All four supplied guides (Silent: Light Baking, Post Processing, Reflection Probes; the Bakery Manual) were read in full; links and per-source caveats in [../SOURCES.md](../SOURCES.md). PP package/client compatibility below is **not** confirmed by a current official VRChat page.

## 1. UVs and density: fix the representation before raising samples

From Silent's baking guide and the manual:

- Lightmap charts must be non-overlapping, inside 0–1, and padded for the **final sampled resolution**. Bakery uses the second UV channel (`Mesh.uv2`, sometimes called UV1 in zero-based tools) when present, otherwise the first. A repeated material UV is not a usable fallback. Enable Generate Lightmap UVs on imported models or author a second set; inspect the actual mesh rather than trusting the checkbox.
- Keep density reasonably consistent; put seams at natural hard edges/hidden boundaries. Align rectangular charts to texture axes where practical. Do not join charts merely to reduce seam count: a low-resolution chart spanning a corner can bleed lighting across it. Give visible bevels enough chart area to resolve their lighting; bevels are a modeling choice, not a mandate to add geometry everywhere.
- Use Bakery **UV validation**, **Checker Preview → Refresh**, then **Atlas Preview** before baking. Check overlaps, tiny islands, wasted space, atlas count and padding. The manual explicitly warns that checker texel sizes are not correct for Terrain.
- **Asset UV Processing → Adjust UV padding** recalculates padding on models with auto-generated UVs using mesh area and bake resolution; the importer-wide Pack Margin is then ignored. Shared assets can have old bakes invalidated by UV changes: consider **UV padding: increase only** across separately baked scenes, or **Don't Change** for shared-model prefab workflows.
- xatlas **unwrapper** and xatlas **atlas packer** are distinct choices. Hole Filling can improve pack utilization at an export-time cost; Post-packing reduces final atlas count. Resolution overrides and efficient LOD packing differ by packer—check the manual's support table rather than assuming every group option works with both.
- The manual's 1–5 texels/unit (large outdoors), 10–20 (smaller outdoors), and 100 (high-quality interior) are **starting examples at 1 unit = 1 m**, not minimum quality requirements. **20 texels/unit does not prove an interior is undersampled.** Base density, renderer Scale in Lightmap, group resolution, chart layout, shadow detail and viewing distance all matter. Confirm starvation in the checker/atlas and rendered result before blaming it for noise.
- **Max resolution** limits individual atlas dimensions; additional atlases can be allocated. Raising it need not raise effective density or total VRAM by a fixed factor. Doubling both dimensions of one equally formatted texture is 4× its texels, not necessarily 4× the scene's lightmap memory.

## 2. Directionality and shader compatibility

The manual supersedes the older guide's limited mode list. Choose output based on **every receiving material**, not just the nicest example material:

| Mode | Stored result / practical use | Compatibility boundary |
|---|---|---|
| None | One color per texel; no directional response to runtime normal maps | Ordinary lightmapped shaders |
| Baked Normal Maps | Normal detail rendered into the color lightmap, no extra directional map | Detail limited by lightmap resolution; can alias or be smudged by denoising; custom normals need a compatible Bakery meta pass |
| Dominant Direction | Color + one direction map; broadly compatible starting point for normal-mapped worlds | Supported by most ordinary lightmapped shaders; weaker/less faithful contrast than SH |
| RNM | Three HDR maps total; more faithful differently colored directional lighting | Requires RNM-aware shader and working bindings; highest memory demand among these manual modes |
| SH | Four maps total, only one HDR; rich directional/color response | Requires SH-aware shader and working bindings; manual reports less memory than RNM but somewhat more shader work |
| MonoSH | Color + monochromatic directional coefficients; contrast similar to SH with reduced directional color fidelity | **Not correct with stock Standard**, even though transported through Unity's directional-map channel |

RNM/SH do not also generate ordinary color lightmaps for incompatible materials. Use group overrides to isolate compatible receivers or choose a compatible global mode. Their additional maps use MaterialPropertyBlocks; seeing only some maps in Unity's Lighting window does not prove data is missing. Silent links [VRC-Bakery-Adapter](https://github.com/MerlinVR/VRC-Bakery-Adapter) for VRChat RNM/SH bindings; it is a 2019 tool (v0.4, unmaintained) that exists because Bakery's runtime binding scripts are not on VRChat's world-component allowlist (still none listed as of 2025-11). It duplicates materials and must be reverted after every upload. Prefer Dominant Direction, or MonoSH (travels in Unity's own directional-map slot, no runtime script) with a MonoSH-aware shader, over RNM/SH in VRChat.

**Specular occlusion and bicubic lightmaps.** Stock Standard keeps full reflection-probe specular in dark lightmapped corners ("Unity shine"), cannot render MonoSH correctly and samples lightmaps bilinearly. Filamented (Exposure Occlusion), ORL Standard (Reflection Probe Occlusion, Bicubic Sampling, Baked Specular) and Graphlit Lit (MonoSH, Lightmapped Specular, Bicubic, Specular Occlusion) fix all three and also read VRC Light Volumes and LTCGI. The workspace shader rule stands: lilToon/Standard by default; offer these only when a reviewer flags shine in dark areas or MonoSH is wanted, and switch only on explicit user approval. z3y/shaders is archived (successor Graphlit).

**Lightmap Specular** is a shader-supported approximation, not a physically accurate reflection or a replacement for reflection probes. It can work better on perturbed normal maps than on flat mirror-like surfaces. Bakery **Volumes** likewise require volume-aware shaders; they cannot be assumed to light arbitrary visitors' avatars and do not replace ordinary Light Probe Groups for that purpose. URP/HDRP support in Bakery's manual does not establish support for those pipelines in VRChat.

**Emission correction:** the manual explicitly supports emissive materials through Meta Pass (or named-property fallback) and requires `MaterialGlobalIlluminationFlags.BakedEmissive`. Emissive receivers need usable lightmap space/UVs and Cast Shadows according to the manual. A missing `BakeryLightMesh` is therefore **not** proof that emission cannot contribute GI. For a visible glow with no bounce, inspect material export, flags, geometry, samples and export-cache freshness. Light Mesh is the separate, explicit, more reliable small/bright-source sampling path; its mesh does not itself receive a lightmap. This corrects the old skill's universal claim that Bakery ignores emission flags.

## 3. Three different probe jobs

### Light probes: diffuse lighting on moving objects

- Light Probe Groups store low-frequency lighting that is interpolated through tetrahedra. Cover reachable player/prop space in 3D, not just one coplanar floor grid; concentrate samples at lighting changes and keep probes out of walls. Inspect dynamic objects across thresholds, rooms and stairs, not only the static lightmap.
- Silent's “tens of thousands are practically free” is a historical qualitative claim, **not a probe-count budget**. Account for data, interpolation/tetrahedralization, baking and actual target performance. Automated placement tools are candidates, not validated recommendations or permission to add scenery colliders.
- The manual now lists **L2** (default; recommended with occlusion probes), **L1**, and **Legacy**. L1/L2 bake with lightmaps and see Bakery's exported scene. L2 stores fuller SH and has small bake overhead relative to L1 according to the manual; neither is a guarantee of zero cost.
- Legacy gathers area/sky/GI using Unity cubemap rendering and is a separate pass. This can capture shader appearance differently, but the manual warns of mismatches from nonphysical shaders or clipped mobile HDR values; it is not automatically “more accurate.” Its Unity 2019.3 occlusion-probe save bug is version-specific history.
- High-contrast light probes can **ring** (including negative/dark lobes). Current manual offers **Ringing removal for L2 light probes** and **Remove ringing in Legacy light probes**; tune those before replacing all shaders. Bakery shader Non-linear Light Probe SH is another option only for materials you control. Silent's speculation that Bakery might add de-ringing is superseded.

### Occlusion probes: mixed-light shadowing

Occlusion data is additional information stored with light probes for mixed-light shadowing on dynamic receivers; it is not a reflection cubemap. Bakery's **Occlusion probes** option delegates this part to Unity's selected built-in lightmapper. Match the intended Shadowmask/mixed-light setup and review avatars in shade. It is not a global substitute for dynamic shadows or a free switch that improves every full-lighting bake.

### Reflection probes: specular environment

- Start with a representative **custom environment reflection** if the skybox is a poor fallback; then add local probes where lighting/enclosure differs. Fit room influence bounds and enable Box Projection for box-like interiors. A cubemap still captures one viewpoint; it is not a true planar mirror.
- Silent simplifies selection to nearest probes/anchor position. Unity 2022.3 documents **renderer-bounds intersection, probe Importance and renderer blend settings**. Large cross-room meshes, their bounds, anchors and shader support deserve inspection; an Anchor Override alone is not a universal fix. Different probe assignments may split batching; measure before merging across spatial boundaries.
- Indoor receivers may need **Blend Probes** rather than **Blend Probes and Skybox**. Do not assume a field toggle guarantees blending: shader and graphics-tier support matter.
- Baked/custom cubemaps are stale when surroundings change. For discrete lighting states, switch matching pre-baked probes/textures together with other lighting data, at a storage cost. Realtime probes are an explicit measured trade-off involving six views/filtering/update scheduling, not a cheap default.
- Bake larger and lower the cubemap import Max Size for a supersampled smaller result if aliasing needs attention. The guide's “512 = 2 MB” depends on format, compression and mip chain; measure imported/runtime memory rather than budgeting from that number.
- A point light has no visible luminous shape for a cubemap to capture. Actual bright fixture geometry or carefully scoped bake-only specular proxies can supply highlights; Silent links [SpecularProbes](https://github.com/zulubo/SpecularProbes). Compatibility was not checked and no tool installed. Avoid double-counting highlights when a shader already supplies baked specular.

**Workspace policy, stronger than source suggestions:** rebake reflection probes **immediately after every lighting bake, including drafts and selective bakes**. Use Bakery's Render Reflection Probes or a verified explicit per-probe bake path, not Unity Generate Lighting/Auto Generate. The manual's **Project Settings → Bakery → Always render reflection probes** can automate this where installed; verify it covers the actual selective/scripted path. Confirm capture eligibility (`ReflectionProbeStatic`, separate from `ContributeGI`), textures assigned, and representative glossy surfaces. Custom references can be cleared in workspace Bakery workflows; retain/reassign and inspect them. “Not worth doing for drafts” is not an allowed exception.

## 4. Post-processing setup and VR comfort

Silent's key workflow insight is to choose the display response **early**, before balancing light intensities, then fine-tune it after lighting. Its “post-process everything,” ACES preference and numeric presets are author advice—not mandatory art direction or a claim of zero performance cost.

For a project using supported PPv2 in the Built-in pipeline:

1. Inspect the existing SDK/package setup first. Do not pin **3.0.3**, manually install a second stack, or buy a replacement from the guide's historical instructions. Current installed/client compatibility remains to be checked.
2. Put **Post Process Layer** on the descriptor's reference camera; use its camera transform as the trigger. Set its **volume layer mask** to the layer used by volume GameObjects. Silent suggests Water as an example; choose according to the actual scene/layer policy, not an assumption that Water is always unused.
3. Keep **No Anti-aliasing** on the PP Layer as the conservative VR setup; do not stack historical PP AA over the client's AA. The guide's exact SMAA/TAA bugs are version-specific, not a current exhaustive compatibility matrix.
4. Create a separate, non-camera-child GameObject with **Post Process Volume**, a profile, and **Is Global** for the baseline. Local volumes use a trigger collider as a functional volume (not a furniture collider), plus blend distance, weight and priority. Enable the individual property override checkboxes; effects blend/override according to active volumes, not merely because a profile exists.
5. Choose tone mapping deliberately: ACES compresses/saturates highlights toward white with strong contrast; Neutral preserves a different color response useful for stylized/saturated emission. No mandatory contrast value, emission value, or universal “correct” curve follows from the guide.
6. Keep bloom restrained; Silent proposes low intensity 0.01–0.3 and low/zero threshold as a starting experiment, **not acceptance bounds**. Avoid lens dirt in VR. Test a white object with emission strength 1 in a lit area: it should not become a blown-out glowing avatar surrogate. Tune light/material emission before trying to repair lighting with grading.
7. Be cautious with Auto Exposure: bright/dark adaptation can make unlit UI, video and avatar materials unreadable. Keep neutral white recognizable and inspect actual menus and visitor avatars. Bloom is added after exposure measurement in the described stack; exposure cannot be assumed to rescue excessive bloom.
8. Prefer comfort-safe defaults: avoid depth of field, chromatic aberration, heavy grain, lens distortion, motion blur and strong vignette for normal VR viewing. The guide reports various effects auto-disabled or stereo-broken in its versions; don't rely on auto-disable. Expensive/eye-dependent screen-space AO is not a substitute for clean baked lighting, and the described SSR path requires Deferred rather than VRChat's Built-in Forward setup.
9. Check both eyes in VR, desktop, reflective surfaces, transparent materials, avatar whites/emission and UI; offer an appropriate effect-disable option where warranted. These checks were **not run** for this documentation task.

## 5. Bake checklist and additional manual levers

- **Before:** save a known-good scene; fix compile errors; confirm target pipeline/platform and installed Bakery/driver compatibility. Keep Unity Auto Generate off and avoid Generate Lighting so it does not replace Bakery data. Check geometry/normals, UV validation, material Meta Pass and actual output path. The manual's **Output path** is configurable and may be scene-named; `Assets/BakeryLightmaps` is not universal.
- **Lighting intent:** Bakery uses its own light components. Match paired Unity/Bakery lights intentionally. Full Lighting bakes direct + indirect; Indirect/Shadowmask require appropriate per-light Baked Contribution and realtime partners. A Bakery Sky Light supplies baked sky illumination; the visible skybox alone does not do that. Keep visible sky, baked sky and reflection fallback consistent.
- **Quality:** hold bounce count fixed while judging brightness. Use the existing two-stage/sample-multiplier recipe; measure actual bake time instead of treating source “free”/“faster” claims as guarantees. AO is optional nonphysical darkening, not proof that physical contact lighting is otherwise broken.
- **Reuse:** disable **Export Geometry and Maps** only when geometry, **textures** and lightmap layout/resolution are unchanged. Disable **Update unmodified lights** to skip unchanged direct-light passes; keep **Update modified lights and GI** enabled to recompute changed lights and bounce. The checkboxes' names are not promises that enabling both performs an incremental-only bake.
- **Resolution/memory:** **Scale per map type** downsizes outputs after rendering—saves storage/bandwidth, **not bake time**; padding follows the lowest-resolution map when UV adjustment is enabled. **Unload scenes before render** can free editor VRAM. GPU Priority/Tile Size trade responsiveness for throughput. Clear Temp cache only when not rendering.
- **Artifacts:** Adjust Sample Positions can reduce leaks but may fail on large smooth low-poly meshes; A/B that option rather than treating it as always correct. Fix Seams blends UV discontinuities; Fix Bright Edges targets denoiser fringes/fireflies. Neither replaces valid UVs and sufficient samples.
- **Compression:** choose platform-appropriate lightmap encoding/compression and inspect dark gradients. The manual supports per-asset override, force compression or force uncompressed. Uncompressed is a useful diagnostic, not technically “unshippable”; shipping it requires a measured memory budget. High Quality Direction can improve desktop maps at higher memory cost. BC6H desktop advice is not an Android format guarantee.
- **Version-sensitive extras:** Terrain Optimization has hole/RTX limitations in the manual. Colored cutout transparency and Light Filter are separate paths; ordinary alpha is otherwise cutout, and Dither Transparency behavior is version-dependent. Do not enable global **Shader Tweaks** casually: they patch the editor's CGIncludes for every project using that editor, and do not cover SRPs. Prefer already-compatible project shaders.
- **After every bake:** complete/verify light probes for the chosen mode, **immediately bake reflection probes**, restore custom bindings as needed, then review static surfaces + moving-object diffuse lighting + specular response with the final camera/post profile. Geometry-changing rejected selective bakes are not successful output; use the existing recovery guidance. Final `final-reviewer` SHIP IT approval remains the workspace gate for actual scene work.
