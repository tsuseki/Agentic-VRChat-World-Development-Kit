**When:** Setting up or debugging VRC Light Volumes (red.sim.lightvolumes) with Bakery.
**Version scope:** these rules were measured on `red.sim.lightvolumes` **2.1.x**. 3.0.0 is a dev pre-release (as of 2026-10). Migrating to dev.12+ deletes the editor helper (authoring) components, drops LV 1.x data and the old volumetric shadowmasks, and cannot be downgraded easily: back up the scene files first, re-verify every rule here, and check dependent packages (LTCGI, GLIM, lilToon, VizVid) compile against the new `LightVolumes.cginc` (GLIM#13 and LTCGI#48 broke during the dev cycle). Treat it as a migration task, not a version bump.
**Rules:**
- With Bakery, keep **Compress volumes** off (`renderSettingsCompressVolumes = false`; both `ftLightmapsStorage` and `ftGlobalStorage` carry it) while on LV 2.x: compressed (BC7) Bakery volume textures are rejected at pack time ("unsupported texture format … must use RGBAHalf, RGBAFloat, RGBA32 or ARGB32"). LV 3.0 auto-fixes this (LV#95, 2026-08).
- Setup limits (LV 2.x docs): unique GameObject name per baked volume (the 3D textures inherit it and collide); ≤32 active regular volumes and ≤128 active point-light volumes (toggle at runtime for more); overlap neighbours ~0.25 m with Smooth Blending below the overlap; doubling Voxels Per Unit ≈ 8× file size; point-light-volume Area type ≈ 8× the cost of point/spot, so bake a regular volume shaped like the light when it doesn't move. Bakery volume rotation needs a current Bakery patch (Bakery → Utilities → Check for Patches). Fix Light Probes L1 corrects Bakery L1 over/under-exposure but lowers contrast slightly.
- Check shader names (`FindObjectsOfType<Renderer>()`) first. If no world material is LV-aware (lilToon, Poiyomi), volumes only light avatars; with a lightmapped interior, probes-only may be strictly better. Removing volumes can expose probe defects they were masking — re-measure probes right after.
- `LightVolumeSetup` hooks `ftRenderLightmap.OnFinishedFullRender`: after every full render it re-pulls BakeryVolume textures, runs the L1 probe fix, and regenerates the atlas (console: "N Light Probes fixed!" + "Generating 3D Atlas finished!"). A probe-only render does NOT fire it — invoke `FixLightProbes` (private **static**; reflection needs Static flags) + `SyncUdonScript` manually.
- Volume resolution is owned by the `LightVolume` component (`VoxelsPerUnit`, AdaptiveResolution); editing BakeryVolume resolution gets overwritten.
- Voxels inside bedding/floors bake near-black without being flagged invalid (thin cloth defeats the backface test); higher density makes it worse. Post-bake fix that worked: per-column "darkness clamp" walking down from below the ceiling (never from the volume's top layer — above-roof sky floods the interior white), replacing voxels with L < 0.45× the voxel above, applied to all three textures.
- Run exactly one `GenerateAtlas()` + `SyncUdonScript` afterwards, never concurrent with the bake's auto-repack — overlapping runs corrupt the atlas (objects blow out white).
**Verify:** A/B by disabling the Light Volume Manager object to see probes-only lighting. LV-aware shaders prefer the volume over probes in scene view.
