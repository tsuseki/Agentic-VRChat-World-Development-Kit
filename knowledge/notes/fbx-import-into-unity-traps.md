- **Child transforms carry the axis fix.** FBX exported without baked space transform keeps mesh data in Blender space; each child node has `localRotation ≈ (270,0,0)`. A scripted importer that builds its own GameObjects (instead of instantiating the model prefab) MUST copy `localPosition/localRotation/localScale` from the source `MeshFilter` transform. Dropping it lays the whole model on its side, which in a large map renders as a horizon running vertically up the screen rather than as something obviously broken. Under a root in Unity's frame the fix is `Euler(0,180,0) * src.localRotation`.
- **`sharedMesh.bounds` is mesh space, so `.y` is not height** when the child is rotated (mesh-local Z is up). A 0.25 m-tall crate read as "0.41 m tall". Any question about height, seating or which way up a prop sits must use `renderer.bounds` (world space).
- **Static flags are per-GameObject.** Flagging a prefab root leaves child renderers out of the bake; see [static-editor-flags-do-not-propagate-to-children](static-editor-flags-do-not-propagate-to-children.md).
- **Poly Haven FBX models** (besides the 1/100 scale) can import Z-up lying face-down: rotate X by -90. Pivots are often mid-height or at the back edge, so re-seat by renderer bounds, not pivot. Some furniture packs import the same way. More Poly Haven import details: [polyhaven-fbx-import-and-terrain-detail-density](polyhaven-fbx-import-and-terrain-detail-density.md).
- **Material remap by name:** create Standard materials named exactly like the Blender materials, then `importer.SearchAndRemapMaterials(ModelImporterMaterialName.BasedOnMaterialName, ModelImporterMaterialSearch.Everywhere)`. Reusing material names across FBXs auto-remaps new models onto existing materials.
- **Round-tripped FBX scale:** a metre-authored FBX (fileScale = 1) can come back from Blender declared in centimetres and import 100x small. Fix on the new importer: `useFileScale = false, globalScale = 1`.
- **Round-tripped FBX slot order:** a Blender round-trip can reorder material slots, so the scene renderer's material array feeds the wrong submeshes. Without touching the original: import materials on both FBXs, read per-submesh material names from each prefab's `MeshRenderer`, then permute: `newSceneMats[j] = sceneMats[origOrder.IndexOf(newOrder[j])]`.
- **Default-UV box screens show a zoomed crop:** the front face of a default-UV Blender box only spans a sub-rect of 0..1 (e.g. u 0.375-0.625, v 0.75-1.0). Per material set tiling = 1/range and offset = -min/range on `_MainTex` and `_EmissionMap` (measure the front-face UV rect by filtering triangles on world normal).
- **Winding checks:** per-triangle `Cross(b-a, c-a)` in local space gives the render-facing direction. To find what really occludes a spot, scan world-space triangle **centroids** of every renderer whose bounds intersect the region; vertex-window scans miss big quads whose corners lie outside the window.
- **Static props import with no rig and no animation.** A rigged or animated FBX (or an avatar prefab) used as decoration gets an `Animator` (plus bones) on every instance, which costs CPU each frame even with nothing playing (Luna 2021; Unity 2022 spends `Animators.IKAndTwistBoneJob` time even on empty layers, forum 48344). For static prop FBXs set `importer.animationType = ModelImporterAnimationType.None` and `importer.importAnimation = false` (Rig → Animation Type: None, Animation → Import Animation off), and reimport so no Animator is added on instantiate. For instances already placed, remove `Animator` components with no controller or no clips and the unused armature. The per-prop cost is unmeasured: measure the delta with a disable-one-at-a-time sweep before quoting a saving.
