---
title: A domain reload mid-bake kills Bakery's export — and Bakery can trigger it itself
topic: lighting-baking
tags: [bakery, domain reload, export, terrain, out of memory, lightmap binding, recovery]
summary: Any script compile, asset refresh or native-plugin reimport during a bake kills Bakery's export coroutine, leaves stale temp objects, and can wreck lightmap bindings; know the tells and recovery steps.
---
**Symptom:** Bake starts (`bakeInProgress=True`) then dies with no dialog; or every later bake fails with "Error exporting scene"; or the scene renders unlit after a cancelled bake; or export dies with OutOfMemory / hangs at "Exporting scene - preparing...".
**Cause and fixes:**
- **Your own edits:** compiling/refreshing while `bakeInProgress` reloads the domain. Queue edits until the bake ends.
- **Pending, never-imported script edits from before the bake:** Bakery calls `AssetDatabase.Refresh` itself (e.g. in `InitializeLightProbes`). `.cs` files edited on disk, for example by another agent, but not yet imported compile at that moment and kill the bake about 1 minute in. Before launching, run a forced refresh with compile, wait until the editor is ready, and check for `error CS`. A comment-only edit saved after that compile is enough to kill it.
- **A refresh requested right before the launch:** a Unity MCP `refresh_unity` with `compile=request` issued seconds before `RenderButton` left a recompile pending; Bakery's own refresh then ran it ("Initiated by StopAssetImportingV2(ForceSynchronousImport | ForceDomainReload)", compile time 0) and the bake died after 40 s. Compile well before, then wait ≥ 20 s with `EditorApplication.isCompiling` and `isUpdating` false and call no refresh before launching. In that case Bakery had already saved the scene with empty storage: restore the scene file (and `_tempScene`, its `LightingData.asset`, the probes asset) from git and reopen it before relaunching.
- **Bakery's own reimport:** with `ftGlobalStorage.renderSettingsUnwrapUVs = true`, export calls `ReimportModifiedAssets` → model postprocessor `Unwrap`; reimporting a native plugin forces an assembly reload. If every bakeable renderer already has UV2 (count ContributeGI + receiveGI renderers with empty `uv2` first), set `renderSettingsUnwrapUVs=false`, `renderSettingsForceDisableUnwrapUVs=true`, and EditorPrefs `kAutoRefresh=false` during the bake. Also set `renderSettingsUVPaddingPreserveIfExisted = true` — default false re-unwraps and discards authored UV2.
- **Stale `__ExportTerrain*` objects:** an interrupted export leaves `__ExportTerrainParent`/`__ExportTerrain` under terrains; every later bake throws `ArgumentOutOfRangeException` in `ftBuildGraphics`. Delete all objects named `__ExportTerrain*`, save, rebake.
- **`renderSettingsExportTerrainTrees` = on** in a scene with tens of thousands of terrain trees: each tree becomes bake geometry → huge Editor.log, OOM in `exportIB32`, eternal export wedge. Grep the scene file for the flag and turn it off.
- **Cancelled/failed bakes** clear `ftLightmapsStorage.maps/idremap/mapsMode` and leak managed memory (tens of GB) in `ftBuildGraphics` statics so the next export OOMs. Free it with `EditorUtility.RequestScriptReload()`; never leave a cancel unfollowed by a successful bake or a domain reload.
- **Rebinding without a rebake:** if atlases on disk are current and renderers' `lightmapIndex`/`lightmapScaleOffset` were not re-packed, read the index→group mapping from the renderers, refill `storage.maps`/`dirMaps` with `<group>_final.hdr` / `_dir.tga` in index order, `mapsMode` per entry (1 = CombinedDirectional), trim `lightmapHasColor/Dir/RNM/Mask` and `bounds` to the same length, SetDirty, save, reopen. `ftLightmaps.RefreshFull()` is a no-op when `maps` is empty. Unity will not serialize `m_Lightmaps` while a LightingDataAsset is assigned.
**Verify / tells:** No `ftrace*` process ever appears (the tracer launches only after export) and Unity's working set collapses (e.g. 3.5 GB → 0.6 GB) = domain reload. Trust `*_final.hdr` mtimes, not `probes.asset`. Bakery logs INFO with stack traces, so a trace alone is not an error. After a dead export check `SceneManager.GetActiveScene().name` — you may be in Bakery's `_tempScene`; reopen the real scene from disk.
